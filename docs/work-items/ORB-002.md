# ORB-002 — Persistent agent create/edit (R01/R03)

## Scope and acceptance criteria

- Load real SQLite profiles after authenticated connection; create and edit every existing profile field in the desktop UI, with no sample agents.
- Preserve UUID and all profile configuration across provider/model changes and engine restarts.
- Reject whitespace-only name, role, seniority and model; expose correct 401/404/422 responses.
- Provide labeled controls, cancel without writes, pending-save feedback, recoverable save/network errors, and memory-only session tokens.
- Keep configured tools empty by default and explicitly separate configuration from execution. No execution or permission grant is introduced.

## Implementation and API contract

`GET /v1/agents/{agent_id}` retrieves a profile. `PUT /v1/agents/{agent_id}` replaces its configurable profile using the existing `AgentInput` representation and returns the same UUID. Clients must send the complete profile when editing; omitted optional fields use their existing create defaults. Missing IDs return 404, unauthenticated requests 401, invalid profiles 422. Auth applies to both routes. Exact-origin CORS permits only GET, POST and PUT.

The update is one parameterized SQLite statement and does not insert missing IDs, change ordering or alter schema version 1. Name, role, seniority and model are trimmed and must contain non-whitespace text. Skills retain the existing `list[str]` contract, including version-qualified references; no skill registry is claimed. There is no new permissions field or grant mechanism.

The UI copies every configurable field into the editor and sends the full profile on save. Expertise, skill references and tool names use one entry per line (blank lines are omitted when saving). Provider/model changes leave the other fields intact. Failed saves retain the draft for retry; cancel performs no request. Save controls are disabled while pending. Reconnect is disabled while editing to avoid discarding drafts. The current authenticated session is independent of token-input changes and exists only in React state; no browser storage is used.
