# ORB-003 — Project inspection and task worktrees

Implements R02/R08 as a standalone Python service. SQLite registration, API/UI wiring,
permissions storage and lifecycle reconciliation belong to ORB-005. No shared API,
provider, database, frontend or roadmap files are changed.

## Contract

`orbit_engine.projects.inspect_project(root) -> ProjectInspection` accepts an
existing absolute canonical checkout root (`str` or `Path`). Relative paths,
symlink aliases, traversal, subdirectories, non-repositories, partial/promisor
clones and bare repositories
are rejected with `ProjectError`. Resolve an alias explicitly before presenting it
for approval. Primary and linked worktree roots are both supported.

The frozen result contains `root`, `git_directory`, `common_directory`,
`head_sha` (None for unborn branches), `branch` (None for detached HEAD), and
`status_porcelain` (Git porcelain v1, NUL-delimited, including untracked files).
Inspection makes no Git writes; optional Git index locks are disabled. It reports
status rather than requiring a clean primary checkout. Callers must preserve NUL
records and escape filenames for their display context.

`orbit_engine.worktrees.create_task_worktree(project_root, *, approved_parent,
task_name, branch, base_sha) -> TaskWorktree` requires:

- A root accepted by inspection and an existing canonical parent approved by the
  caller, outside all this repository's checkouts and its common Git directory.
- A unique task directory name: 1–80 ASCII letters/digits/underscore/hyphen,
  starting with a letter or digit. Destination must not exist, even if empty or
  a dangling symlink.
- A unique branch: 1–120 ASCII letters/digits/slash/underscore/hyphen, starting
  with a letter/digit, with no empty or hyphen-leading components; Git also checks
  branch syntax. Existing branches are refused; Git rechecks collisions at creation.
- A full lowercase 40- or 64-character object ID that already exists locally and
  identifies a commit. Branch names, abbreviated SHAs, revision expressions,
  options, tags and non-commit objects are not accepted as bases.

The frozen result records `project_root`, `base_sha`, `branch`, and `path` for later
persistence. One argument-array `git worktree add -b` operation creates the branch
and checkout. Git hooks and filesystem monitor commands are disabled; inherited
`GIT_*` routing/configuration variables are removed. Lazy fetching is disabled;
partial/promisor configurations are rejected before object inspection, including
on Git versions without the lazy-fetch environment switch. No shell is used. Each Git
invocation has a 30-second timeout. Git errors surface as `ProjectError` without
including repository-controlled stderr in user-facing messages.

## Failure and caller responsibilities

There is deliberately no fetch, push, merge, stash, reset, removal or automatic
rollback. A failed/timed-out add can leave a branch, checkout or administrative
record. Inspect these explicitly before retrying with a new unique name; never
assume failure means nothing was created. No failure path deletes user data.

The caller supplies access approval and must serialize creation requests and keep
approved directories/ancestors stable while the operation runs. Path checks are
not protection against another process replacing directories concurrently. Git
worktrees share objects, refs and repository configuration; they provide Git
change isolation, not a process security sandbox. This service does not authorize
arbitrary tool execution or protect against hostile Git installations/configuration.
Inspection and creation are point-in-time operations, not atomic registry updates.
A parent may contain spaces/metacharacters; shell interpolation never occurs.
