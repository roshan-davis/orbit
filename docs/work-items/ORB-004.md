## Scope and acceptance criteria

Implements the discovery portion of R07 and honest local compute reporting through
`GET /v1/providers`. The existing list and all existing provider fields remain;
only Ollama gains a `discovery` object. All providers retain disabled execution,
cloud authentication remains unknown, and energy metrics remain unknown/null.
The legacy Ollama `auth: local` describes its route, not authenticated readiness:
`discovery.authentication` is explicitly unknown and `execution_ready` is false.

- Only fixed `http://127.0.0.1:11434/api/tags` is queried with GET, no credentials.
- No environment host/proxy, DNS lookup, redirect, cloud request, subprocess,
  model pull, inference, provider activation, or cloud authentication check.
- A 500 ms network deadline spans connection, headers and body reads; the socket
  reapplies the remaining deadline on every receive, including slow trickles.
- Body limited to 256 KiB, inventory limited to 256 models. No retries.
- Discovery reports `available`, `empty`, `offline`, `timeout`, `malformed`,
  `redirect_rejected`, `http_error`, or `invalid_endpoint`. Reachable means only
  that an HTTP response arrived, never execution or authentication readiness.
- Model metadata uses an allowlist of bounded printable strings and nonnegative
  integer size. Unrecognized fields and unsafe optional values are omitted;
  invalid inventory structure/name fails closed. Errors never echo server bodies
  or exception messages. Gemma/Qwen appear only when reported in the inventory.
- Tool capability remains unknown; tags do not establish model tool support.

## Contract evidence

Official Ollama docs inspected October 31, 2026:

- [List models](https://docs.ollama.com/api/tags): GET `/api/tags`, `models` list,
  name/model/modified_at/size/digest and details (format, family/families,
  parameter_size, quantization_level).
- [Introduction](https://docs.ollama.com/api/introduction): distinct local and
  cloud endpoints; local requests do not require authentication. Local service
  reachability does not establish that a model can execute locally: a local
  server may also expose cloud model entries. This discovery is inventory only.

## Limitations and review

This is inventory discovery only. No execution, local memory/load measurements,
capability negotiation, model validation or authenticated readiness is implemented.
A reported model is not proof of local inference support; cloud model entries
are never executed. Requests perform a fresh bounded probe (no cache); the sync
FastAPI endpoint runs in its worker pool. No live Ollama or cloud smoke tests.
Frontend/native desktop were unchanged and not validated; Rust is unavailable.
Independent agent review found no blocking issues and reran all 36 tests. The
user explicitly authorized merging after successful review and validation.
