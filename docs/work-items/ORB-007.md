## Implemented contract

Schema v4 transactionally adds runs with a unique assignment ID. Claim, task
state/version and audit event share one write transaction; finish does likewise.
One worker per database is protected by an OS advisory lock; a second engine
refuses ownership. Restart marks running records failed and cancellation requests
cancelled, retaining worktrees and never invoking inference again. Failed/cancelled
tasks are terminal under ORB-006; create a new task rather than silently retrying.

Authenticated endpoints:

- `POST /v1/tasks/{id}/runs`: `{expected_version, approved_parent, files,
  grant_file_access: true}`, returns 202 with run history. Only assigned Ollama
  snapshots with complete dependencies may start. The explicit request grants
  only listed file reads/replacements; agent `tools` strings grant nothing.
- `GET /v1/tasks/{id}/runs`: persisted IDs/status/binding/logs/stored diff.
- `POST /v1/tasks/{id}/runs/cancel`: `{run_id}`. A stale ID conflicts. Cancellation
  persists before signalling the worker. File application and cancellation are
  serialized; no file writes occur after a successful cancellation response.
  Refresh until the worker reports its terminal outcome.

The worktree parent must already exist outside all project checkouts/Git metadata.
The recorded project HEAD, not uncommitted changes, is used. The model receives
only the task, bounded instructions and explicitly named files from that commit.
At most 16 ordinary UTF-8 files and 64 KiB combined context are supported; no hidden
paths, traversal, symlinks, multiple hardlinks, secret filenames, binary files,
missing parent directories, deletes, shell tools or automatic tests. Obvious
credential patterns in context are blocked; this heuristic is not a general secret
classifier. Users must grant only appropriate non-secret files and instructions.

Fixed loopback `/api/show` must report completion capability, no remote fields and
a readable regular local SHA-named GGUF blob with the GGUF header. Cloud-like model
names fail closed. `/api/chat` uses nonstreamed JSON with bounded output/tokens and
120-second network deadlines. No redirects, proxies, environment hosts, credentials,
cloud fallback, pulls or model-generated commands. Official contracts checked:
[show details](https://docs.ollama.com/api-reference/show-model-details) and
[chat](https://docs.ollama.com/api/chat). GGUF validation is an intentionally narrow
local policy; unknown formats fail closed. The local Ollama service/model registry
and OS are trusted and must not be concurrently replaced or reconfigured. Local
weights verification does not authenticate a malicious local service or pin aliases
against an external process. Native tool capability is not claimed.

Fixed phase messages provide bounded logs without storing model reasoning/prompts
or raw server errors. Successful file replacements generate a stored unified diff
and enter awaiting_review, never automatic completion. Desktop controls expose
explicit grants/start, manual status/log/diff refresh, cancellation, actual-review
assertions using a distinct configured reviewer and explicit completion approval.
These assertions are made by the trusted human session holder; they do not execute
an independent reviewer and never merge Git. The UI renders diffs as escaped text.

## Limits and review status

One local run per database; manual refresh rather than SSE. Cancellation disconnects
inference and prevents file application but does not guarantee immediate GPU unload
inside Ollama. Filesystem and SQLite cannot form one atomic transaction: a crash or
write failure may retain partial files without a successful stored diff. Such runs
fail on recovery, never repeat, and retain their recorded worktree for inspection.
File/path checks assume stable local directories, as ORB-003 documents; this is not
an OS security sandbox against hostile concurrent filesystem/Git configuration.
No commits, tests, merge, cleanup or skill loading occur in the product runner.
Instructions beyond 16,000 characters are currently truncated for context bounds.

Engine startup and session token entry remain manual. A connected native end-to-end
flow and independent code/diff review are not yet verified. This is a working local
execution preview, not a claimed accepted Phase 1 release. Independent review by
Rosh/Claude or another reviewer distinct from the author and explicit Rosh merge
authorization remain required. PR remains draft until those gates are satisfied.
