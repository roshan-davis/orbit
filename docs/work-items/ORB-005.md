## API and storage contract

Schema v2 adds `projects(id PRIMARY KEY, name, root UNIQUE, git_directory, common_directory)`, with all fields non-null. Migrations acquire `BEGIN IMMEDIATE`, re-read the version under the write lock, and commit DDL and `user_version` together. Version 1 agent JSON is unchanged, including legacy readable profiles. Unknown schema versions fail without advancing the version. SQLite foreign keys, WAL and parameterized writes remain enabled. Concurrent first-time WAL setup may contend and fail startup; retry startup rather than treating a failed initialization as ready.

All routes require the existing bearer token:

- `POST /v1/projects` accepts `{name, root}` and returns 201 with UUID plus stored Git directory identity. Name is trimmed, nonblank, at most 120 characters; root is at most 4096 characters. Root must pass the existing canonical checkout inspection. Invalid input is 422; duplicate roots are 409, enforced by SQLite even for concurrent requests.
- `GET /v1/projects` lists stored registrations in insertion order, including unavailable roots, without probing Git or claiming readiness.
- `GET /v1/projects/{id}` freshly inspects the registered root and compares Git/common directory paths. Missing ID is 404; unavailable or changed checkout identity is 409. No repository-controlled error output is exposed. Status/head are intentionally not persisted as readiness evidence.

The desktop loads registrations on connection, leaves selection empty, registers an explicitly entered root, and validates an existing selection through GET. Selection lasts only for the connection; reconnect clears it. Successful registration selects the freshly inspected result. Failures retain registration inputs and clear failed selection. Tokens stay in page memory. Registration grants no execution permission. Listing can show stale registrations so users can diagnose unavailable roots; no automatic cleanup deletes them.

The reused service accepts primary and linked worktrees and dirty/unborn checkouts, rejects symlink aliases, traversal, subdirectories, bare and partial/promisor repositories. These are point-in-time checks, not filesystem sandboxing or proof against concurrent directory replacement. Comparing Git directory paths cannot detect replacement by a different repository using exactly the same paths. Future task execution must revalidate its own boundaries and approval; a stored registration is never sufficient authority by itself.
